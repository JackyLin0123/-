# 固定模型与手算对照

模型和停止/错误条件以README为准。此文件记录运行之前确定的预期，不由程序输出反向生成。

## 顺序轨迹

初始PC=0，x2=0、x4=2、x6=3、[0]=7，其余0。

| 指令地址/操作 | 读取 | 结果与下一PC |
|---|---|---|
| 0：lw x1,0(x2) | 地址0，内存值7 | x1=7，PC=4 |
| 4：add x3,x1,x4 | 7和2 | x3=9，PC=8 |
| 8：add x5,x3,x6 | 9和3 | x5=12，PC=12，按项目末尾规则停止 |

## 完整转发时空图

| 指令 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| lw | IF | ID | EX | MEM | WB | | | |
| 第一条add | | IF | ID | ID保持 | EX | MEM | WB | |
| 第二条add | | | IF | IF保持 | ID | EX | MEM | WB |

第3拍末检测load-use，冻结下一拍IF/ID并向EX插入气泡。第5拍第一add由MEM/WB接收7；第6拍第二add由EX/MEM接收9。共8拍。

## 关闭转发

| 指令 | IF | ID（可能多拍） | EX | MEM | WB |
|---|---:|---|---:|---:|---:|
| lw | 1 | 2 | 3 | 4 | 5 |
| 第一条add | 2 | 3、4、5 | 6 | 7 | 8 |
| 第二条add | 3、4、5（冻结） | 6、7、8 | 9 | 10 | 11 |

第5/8拍前半写、后半读使消费者能在生产者WB同拍完成ID，无需多等一拍。最终状态仍须与顺序执行相同。

## 分支与Cache预期

branch输入中PC=4处beq x3,x3,12转到16。PC=8的store和PC=12的addi都不能留下架构副作用，[4]=0、x7=0、x8=1。EX决议与MEM决议的冲刷槽不同，最终状态相同。

四行直接映射、4B块、冷启动访问0,4,0,16,0：

| 地址 | tag | index | offset | 命中/替换 |
|---:|---:|---:|---:|---|
| 0 | 0 | 0 | 0 | 缺失，放块0 |
| 4 | 0 | 1 | 0 | 缺失，放块1 |
| 0 | 0 | 0 | 0 | 命中 |
| 16 | 1 | 0 | 0 | 缺失，块4替块0 |
| 0 | 0 | 0 | 0 | 缺失，块0替块4 |

写回+写分配W0,W16：第一次装入置脏，第二次淘汰脏块0，故下层写事务1、字节4；当前块4仍脏，未自动flush。写直达+不分配同输入：两个写缺失均绕过，下层写事务2、字节8，Cache仍空。

实际结果在run.py指定的输出目录中单独保存；不要将本文件的预期当成运行证明。
